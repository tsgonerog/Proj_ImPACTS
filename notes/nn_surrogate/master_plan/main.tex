%  NAMING. The number is the file's position in the document, so that the

%  reads in the same order as the PDF. The name says what the file is; the

%  sections/, add one \input below. Nothing else moves. If it has to go
%  between two consecutive numbers, renumber only within that decade -- the
%  other blocks are ten away and never affected.
%  To REMOVE one: delete the file and its \input. Leave the hole; a gap in
%  the sequence is not a defect and renumbering to close it is churn.
%
%  A reviewer of the resource request needs Part I and the appendices only:
%  comment out the Part II \input below and the document still compiles,
%  minus the cross-references into it.
%
%  THIS IS THE MASTER DOCUMENT. Everything in ../briefs/ is derived from it
%  and must stay consistent with it: when a section here changes, re-read
%  the briefs that ../briefs/README.md lists against it. Nothing flows the
%  other way -- a correction made in a brief belongs here first.
%
%  Two briefs are derived from this document. Each has its own preamble and
%  shares no file with this one, so each can be its own Overleaf project -- but
%  all three also build together when notes/nn_surrogate/ is uploaded as a single
%  project, which is the usual arrangement here:
%
%    ../briefs/surrogate_concept_note/    two pages of PART II, for a first reader
%    ../briefs/perturbation_experiment/   two pages of PART I, plus the request
%
%  Both are capped at three pages. See ../briefs/README.md for which one has to
%  be re-read when which part of this document moves.

%  INPUT PATH. Overleaf compiles from the PROJECT ROOT, not from the folder the
