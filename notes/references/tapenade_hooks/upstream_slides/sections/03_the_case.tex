\begin{frame}{Why the TAF and OpenAD paths are unaffected}
  \framesubtitle{Five independent reasons}

\begin{enumerate}\small
  \item \textbf{The preprocessor removes the additions.} Every source change
        has the form \cpp{ifdef ALLOW_TAPENADE} $\ldots$ \cpp{else}
        \emph{checkpoint69m text verbatim} \cpp{endif}, so the TAF and OpenAD
        front ends never see them.
  \item \textbf{The hooks are differentiated by no tool.} None of the four
        appears in any package's \code{*_ad_diff.list}; they compile as
        ordinary forward sources and remain no-ops.
  \item \textbf{The TAF adjoint files are untouched.}
        \code{addummy_in_stepping.F} and \code{addummy_for_etan.F} are not
        shadowed at all. Under Tapenade they compile as dead code, exactly as
        they do in a stock Tapenade verification build.
  \item \textbf{\code{flow_tap} is read only by Tapenade.} The single file
        whose meaning changes is opened by no other toolchain.
  \item \textbf{The added bodies complete routines that currently return
        immediately.} 639 of the contribution's lines replace \code{RETURN}
        statements in \code{pkg/tapenade}.
\end{enumerate}

\Safe{This is verified rather than asserted. Everything above is delivered
through \code{genmake2 -mods} shadowing, so our vendored copy of
checkpoint69m is byte-for-byte identical to the distribution --- no file
modified, added or removed --- and three mechanical checks confirm it before
each push.}
\end{frame}

\begin{frame}{Summary}

\begin{itemize}
  \item The absence of \code{ADJ*} output from the Tapenade path is a
        \textbf{gap in what MITgcm currently provides}, not a limitation of
        Tapenade. Four hooks carry no active data, and a data-flow-driven tool
        correctly discards them. The \code{adxx_*} gradients were never
        affected.
  \item The change routes each hook's relevance through its argument list, so
        that \textbf{Tapenade generates the reverse-sweep call itself}. No
        patched \code{genmake2}, no frozen copy of generated code, and no
        common-block mirror.
  \item \textbf{124 guarded lines} in six existing files, with bodies for
        routines checkpoint69m already ships as stubs. Every non-Tapenade
        build preprocesses to the distributed source.
  \item Verified bitwise on DINO 1\textdegree{}
        (51\,$\times$\,198\,$\times$\,36, 27 MPI ranks) at 30 days and again at
        5 years, and against a finite-difference gradient check.
  \item \textbf{Beyond this configuration:} the same pattern carried over to a
        second, independently configured setup --- three of the shadowed files
        are byte-identical between them, and the only differences are the two
        mode-switch hooks that setup has no need for.
\end{itemize}
