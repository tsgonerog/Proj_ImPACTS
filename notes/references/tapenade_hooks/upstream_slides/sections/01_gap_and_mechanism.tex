\begin{frame}{The claim}

MITgcm's Tapenade backend already produces \code{adxx_*} control gradients:
those come from \code{pkg/ctrl}'s active-file machinery and involve no hooks.
What it cannot produce is the \code{ADJ*} adjoint-state dumps --- snapshots of
the adjoint fields as the reverse sweep passes each time level --- and it
cannot switch MITgcm's adjoint-mode parameters. Both depend on four routines
that are empty in checkpoint69m.

\medskip
\begin{itemize}
  \item As distributed, a Tapenade adjoint build writes \textbf{no}
        \code{ADJ*} files, and the adjoint-mode parameter switching is
        unreachable from it. \code{pkg/tapenade/dummy_tap.F} supplies those
        routines as empty stubs.
  \item We closed both in the DINO 1\textdegree{} configuration with
        \textbf{124 lines of CPP-guarded addition} across six existing files,
        together with bodies for routines checkpoint69m already ships as
        stubs.
  \item Nothing in the TAF or OpenAD path changes --- verified bitwise.
\end{itemize}

\vfill
\begin{beamercolorbox}[wd=\textwidth,sep=5pt]{safebox}
  \labelface{ImpGreen}{The ask}\ \ 
  Is this the shape a contribution should take --- and should the dump hook
  carry CPP-conditional argument lists, or one fixed superset signature?
\end{beamercolorbox}
\end{frame}

{\footnotesize Tapenade's external-library mechanism is \textbf{purely
data-flow driven} and has no \code{ADNAME} equivalent. An external carrying no
active data contributes nothing to any derivative, so it is \emph{correctly}
eliminated.}

\Strip{ImpAmber}{What it cost}{MITgcm's adjoint-mode parameter switching had
never taken effect under Tapenade, and obtaining \code{ADJ*} output at all
required a patched \code{genmake2}, a frozen 5{,}547-line copy of generated
code, and an \code{adcommon.h} mirror whose member ordering had to follow that
generated code exactly or every dumped field is mislabelled.}
\end{frame}


\begin{frame}[fragile]{The mechanism: activity through the argument list}
  \framesubtitle{Give the hook active arguments, and Tapenade generates the reverse-sweep call itself}

\begin{columns}[T]
\begin{column}{0.48\textwidth}
{\scriptsize\color{ImpSlate}\code{model/src/forward_step.F}:}

\vspace{2pt}
{\scriptsize
\begin{semiverbatim}\color{black!85}
\color{ImpBlue}# ifdef ALLOW_TAPENADE\color{black!85}
      CALL DUMMY_IN_STEPPING(
     &     theta, salt, uVel, ...,
     &     myTime, myIter, myThid )
\color{ImpBlue}# else\color{black!85}
      \color{ImpSlate}CALL DUMMY_IN_STEPPING(
     &     myTime, myIter, myThid )\color{black!85}
\color{ImpBlue}# endif\color{black!85}
\end{semiverbatim}}
\end{column}

\begin{column}{0.49\textwidth}
{\footnotesize
\begin{enumerate}
  \item The call site passes model state.
  \item \code{flow_tap} declares those arguments
        \code{ReadThenWritten} --- active.
  \item Tapenade emits
        \code{DUMMY_IN_STEPPING_B(theta, thetab, ...)}
        at the \textbf{exact mirror} of the forward call.
  \item The hand-written body completes the routine
        \code{pkg/tapenade} declares, and writes \code{ADJ*}.
\end{enumerate}}
\end{column}
\end{columns}

\medskip
{\footnotesize The adjoint state arrives \textbf{as arguments}, which removes
the \code{adcommon.h} common-block mirror, the post-edited generated file, and
the need to repeat either after re-differentiation. For the mode switches a
single field, \code{uVel}, is enough to carry activity across the interface.}

\Safe{The \cpp{else} branch is the checkpoint69m line unchanged, so with
\code{ALLOW_TAPENADE} undefined the preprocessed source is byte-identical to
the distribution. Every source change we made has this shape.}
\end{frame}
